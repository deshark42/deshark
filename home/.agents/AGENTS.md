# AGENTS.md

## 通用约定

- 首次调用工具前，简要说明接下来要做什么
- 任务执行期间持续向用户同步进展。在重要阶段节点或长时间调查过程中，主动提供简短的进度更新，即使没有重要发现。说明当前工作方向和下一步计划，不要逐一播报工具调用，也不要长时间保持沉默
- 不要为代码中显而易见的事实添加注释
- 测试描述的是行为，而不是正确性。当现有行为不再适用时，应同时更新代码和测试，并在变更总结或 PR 中解释原因
- 对于缺乏自然、通用中文译法的英文技术术语，保留英文原文，不要生造或强行翻译
- 临时文件和草稿工作应放在 `~/tmp/<workspace>/<topic>/` 下，而不是 `/tmp/`

## Git

- 未经用户明确授权，禁止合并分支、推送代码变更或创建 Pull Request 和 Issue。不得将一般性的任务指令视为对上述操作的授权
- 编写提交信息时遵循 Conventional Commits 规范
- 对于简单改动（如重命名字段），Git 提交信息只写一行标题，不添加正文；仅在需要解释改动动机或背景时才添加正文

## GitHub

- `gh` 已安装并完成认证，优先使用它，而不是未经认证的 `api.github.com` 请求

## 记忆

你的记忆系统是 OptMem：
- 工具：`memo`
- 记忆目录：`~/.optmem/memory`

### 子 Agent

子 Agent 不得使用 `memo`。本章节的其他指令仅适用于主 Agent。

创建子 Agent 时，在其指令中写入：`You are a subagent. Don't run memo.`

### 启动时：激活 OptMem（强制）

每次会话中，在调用任何其他工具之前，必须先执行 `memo wake`，然后严格按照其输出的指示执行，直到处理完全部输出内容。

### 工作过程中：记录记忆

当发现可能对未来任务有帮助的信息时，提议将其记录为记忆，例如长期有效的用户偏好、可复用的经验或重要的项目决策。不要记录临时性发现、无关的个人信息或重复的记忆。

每次调用 `memo note` 前，必须通过 `ask_user_question` 向用户展示拟记录的具体内容，并请求明确批准。只能记录用户批准的内容；如果用户拒绝或未作答，不得记录。

使用 `memo note "<1 line, max 280 bytes>"` 保存已获批准的记忆。

如果 `memo note` 要求压缩记忆，必须在执行下一步操作之前完成压缩。

不得直接编辑或删除 `~/.optmem/memory` 下的任何内容，这些内容由工具管理。

### 需要查找旧记忆时：搜索或浏览

`memo recall <regex>` 使用正则表达式逐字搜索所有记忆。

你的记忆也以二叉树形式组织：`#0-1`、`#2-3` 等是单行摘要，相邻的摘要进一步合并为 `#0-3` 等更高层级的摘要，依此类推。`wake` 输出的每一行 `#a-b` 都对应树中的一个节点。`memo zoom <a-b>` 可以将节点展开为两个子节点，逐级深入，直到原始记忆。
